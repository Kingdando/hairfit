# Render deployment

The Render Blueprint deploys three services:

1. `facefit-api` — Node/Express API connected to Supabase Postgres.
2. `facefit-face-analysis` — PHP/Gemini face-analysis API built from [php-api/Dockerfile](./php-api/Dockerfile).
3. `facefit-web` — Expo web static site.

The Expo app uses only the `facefit-api` public URL. The Node API proxies `/api/face-analysis.php` to the PHP service, so the PHP URL is server-only.

## Before creating the Blueprint

1. Push the repository to GitHub, GitLab, or Bitbucket.
2. Create the Supabase project and copy the **Session pooler** PostgreSQL URI from **Connect**. Use the URI exactly as copied, with the real database password.
3. If legacy MySQL data must be preserved, run the one-time migration from a machine that can reach both databases:

   ```sh
   cd server
   npm install
   npm run db:migrate:supabase
   ```

   The migration script reads the temporary source variables in `server/.env.migration`; do not deploy those variables to Render.

## Create the Render services

1. In Render, choose **New → Blueprint**.
2. Select the repository containing this project.
3. Render detects the root `render.yaml` and creates the three services.
4. Provide the `sync: false` values when prompted, then deploy.

## Required Render variables

### `facefit-api`

```text
SUPABASE_DB_URL       Supabase Session pooler URI
SUPABASE_DB_SSL       true
DB_POOL_SIZE          10
JWT_SECRET            generated by Render
GEMINI_API_KEY        your Gemini API key
GEMINI_ANALYSIS_MODEL gemini-3.8-flash
CORS_ORIGIN           final facefit-web URL
FACE_ANALYSIS_INTERNAL_URL  PHP service URL ending in `/api/face-analysis.php`
```

`PORT` is supplied by Render. The pre-deploy command runs `npm run db:init` and creates the Supabase schema before the API starts.

### `facefit-face-analysis`

```text
SUPABASE_URL                 https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY    server-only Supabase service role key
GEMINI_API_KEY               the same Gemini API key
GEMINI_ANALYSIS_MODEL        gemini-3.8-flash
JWT_SECRET                   automatically copied from facefit-api
CORS_ORIGIN                  final facefit-web URL
```

Never expose `SUPABASE_SERVICE_ROLE_KEY` in Expo variables or commit it to the repository.

### `facefit-web`

Only one API variable is injected during the Expo static build:

```text
EXPO_PUBLIC_API_URL                    https://facefit-api.onrender.com
```

Use the actual URLs shown by Render after deployment. Save the variables and redeploy the static site after changing them.

## Verify after deployment

```sh
curl https://facefit-api.onrender.com/api/health
curl https://facefit-face-analysis.onrender.com/health.php
```

The first response should report `database: "connected"`; the second should report `service: "face-analysis"`.

Open the `facefit-web` URL only after both API health checks pass. If the web app was built before the environment variables were added, trigger **Manual Deploy → Deploy latest commit** so Expo embeds the correct public API URLs.
